# ComfyUI-BasicExpansion 設計書

## 1. 目的と概要
ComfyUIのサイドパネル（コンソール等がある場所）に新しい領域（タブ構造）を追加し、拡張機能を直感的に操作できるユーザーインターフェースを提供します。
**なぜこの機能が必要か？**: 既存のComfyUIでは、CheckpointやLora、プロンプトの管理がノードベースに依存しており、全体像の把握やテキストの長文編集が直感的に行いづらいため、独立したタブUIを用意することでワークフロー構築を効率化するため。

## 2. アーキテクチャ構成
本拡張機能は、フロントエンド（JavaScript/HTML）とバックエンド（Python/ComfyUI API）の両面から構築します。

### 2.1 UI設計 (フロントエンド)
- **タブの種類**: `Checkpoint`, `Loras`, `Prompts`, `Images`
- **なぜこのUI構成か？**: ユーザーがよくアクセスするアセット（モデルや画像、プロンプト）をカテゴライズして管理しやすくするため。

### 2.2 機能仕様と調査事項への回答 (バックエンド・連携)
`project.md`の調査項目に対する設計判断を以下に示します。

1. **Loraマネージャの解析に基づくタブ実装**
   - **方針**: 既存の Lora 管理機能のAPI・データ構造を参考に、CheckpointとLorasのリスト取得APIを実装します。
   - **理由**: 既存のシステムロジックを流用することで、ComfyUI本体のアップデートに対する堅牢性を高めるため。

2. **Promptsタブ (テキスト編集とYAML保存)**
   - **方針**: フロントエンドにテキストエリアを設け、入力内容をサーバー側へ送信し、指定のYAMLファイルとして保存・読み込みするAPIエンドポイントを作成します。
   - **理由**: エディタライクな専用UIでプロンプトを管理・保存できた方が、再利用性や視認性が向上するため。

3. **Imagesタブ (ドラッグ＆ドロップ対応)**
   - **方針**: ドラッグ＆ドロップイベントを捕捉し、画像を特定のディレクトリに保存、または直接ブラウザ上でプレビュー描画する領域を設けます。
   - **理由**: リファレンス画像をComfyUI上にシームレスに展開し、i2iなどの作業へスムーズに移行するため。

4. **ハブノードを介したUIと実行グラフの同期（アプローチA）**
   - **方針**: ユーザーにキャンバス上に配置してもらう専用の「ハブノード（例: BasicExpansion Hub）」を作成します。サイドパネルのUIで行われた操作（Loraの追加や重みの変更など）は、JS側からキャンバス上のこのハブノードのウィジェット値を直接書き換えることで同期させます。
   - **理由**: ノードの動的生成を避け、ComfyUIの標準的な実行フロー（ノードのウィジェット値に基づく実行）に則ることで、データ連動をシンプルかつ確実に行うため。

5. **既存ノードの拡張機能からの利用**
   - **方針**: JavaScriptの `app.graph` やPython側の `NodeTemplate` を介して、既存ノードのインスタンス化やパラメータ設定を行います。
   - **理由**: ComfyUIの既存ノード構成を動的に組み立てる方が互換性が担保されるため。

6. **他のインストール済み拡張機能との連携**
   - **方針**: フロントエンドではグローバルの `app.extensionManager` 等のオブジェクトを介して連携を行います。
   - **理由**: エコシステムに則った開発とし、他拡張との干渉を避けるため。
